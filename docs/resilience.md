# WeatherKit 缓存与弱网处理 v4

2026-10-19，版本 `3.3.2-cache.4`。Loon 插件订阅地址保持为 `main/Loon/script/WeatherKit.plugin`，运行脚本固定引用 `cache-v4`，旧 `cache-v3`、`cache-v2` 与 `cache-v1` 保留用于回退。

## v4 减少处理与存储开销

- Loon 功能列表由原生 `response.json.jq` 补齐，保留 Apple 顺序、未知能力并去重；未知结构透传。普通 AQI 标尺的数字版本后缀由原生 URL Rewrite 移除，保留查询参数和条件请求头；仅 GET、HEAD、OPTIONS 生效。这两类路由没有 JavaScript Script 规则。
- HK/CN 自定义 AQHI 标尺使用独立的 `scale.bundle.js`，不读取设置、响应缓存、地图或供应商凭据。预警详情使用独立入口；失败透传时保留原请求的条件头，且 `ids` 位于第一个参数时也能匹配。
- 每次执行中只读取、解析一次响应缓存快照。每次命中仍核对过期时间、数据类型与配置 TTL；真正写入前重新读取、合并其他执行的新条目。容量和现有并发限制不变，仍无持久化事务保证。
- 彩云“昨天空气质量”的小时请求从变化的秒时间戳改为前一天对应的整点，修复同一小时反复刷新无法命中的缓存。仍使用原有 180 秒预报有效期，跨小时立即换查询键，不缓存过期数据。
- 未启用替换、不在替换地区、只透传的数据项不解码、不复制，也不构造供应商对象。已有 Apple 下一小时表仅检查表是否存在，保持原有保留行为；发生替换时继续保留其他根表。已有 Uint8Array 正文复用原视图。
- 离线地区多边形按真正需要的坐标推断延迟解析；明确国家和 Locale 模式不构造整张点表。相同坐标与国家的确认记录每小时最多写一次，国家改变、到期和时钟回退仍重新处理。
- Loon 独立入口移除无条件启动／结束日志，供应商版本日志遵守 LogLevel。可选诊断保留；没有需要处理的数据时不会构造协调器或生成空统计。
- 修复和风昨日 AQI 对比未传入可选转换函数时的异常；无效类别 -1 不再参与昨日比较，会按既有路径获取合法类别。

默认新鲜度、缓存容量、请求预算、最多三个活跃请求与功能开关均保持不变。没有后台轮询、新增权限或设备设置变更。可复现实验及限制见 [处理开销对比](power-work.md) 和 [原始测量](power-work-measurements.json)。

## v3 修复内容

- 严格拒绝回调返回的 HTTP 鉴权失败、限流、3xx 状态、服务器错误和不合法正文；错误正文即使伪装成成功 JSON，也不会交给天气转换器。和风实况的温度还必须为有限数值。
- 共享同一次原生网络响应时，各数据项分别校验自己的结构与正文长度；预警子项失败不会使正常实况失效。有效完整响应仍可跨实况与预警复用缓存，不增加正常链路的请求数。
- 传输错误按实际原生请求计数，正文错误按数据类型隔离冷却；避免六个共用消费者把一次服务器错误计为六次。关闭缓存的 WAQI 鉴权请求也参与冷却，只持久化身份哈希和时间，不缓存令牌响应。WAQI 表单令牌按 URL 编码发送，普通 AQI 日志不再包含令牌。
- Loon 供应商请求直接使用官方 `$httpClient` 回调与毫秒 timeout，避开共享工具库对短毫秒值的秒制转换。每次发起前仍检查预算；边界测试覆盖 250、499、500、501、999、1499、5000 毫秒，以及真实 QWeather 适配链路仅剩 499 毫秒的情况。其他客户端沿用原有适配器。
- 地区网格的原生 304 空正文可保留既有数据并刷新检查时间，不误记为失败；供应商返回 undefined 的失败路径也正确计入数据项回退。

## 默认参数

| 参数 | 默认值 | 范围与行为 |
| --- | --- | --- |
| `RequestCache.TTL` | 60 秒 | 实况与空气质量；0 禁用全部已完成响应缓存，仍合并在途请求；最高 300 秒 |
| `RequestCache.ForecastTTL` | 180 秒 | 小时与每日预报；最高 300 秒 |
| `RequestCache.MinutelyTTL` | 15 秒 | 分钟降雨；最高 30 秒 |
| `RequestCache.AlertsTTL` | 15 秒 | JSON 与已解析的网页预警；最高 30 秒 |
| `RequestCache.BudgetMs` | 8000 毫秒 | 网络发起预算，1000–15000；不会取消原生请求或提前调用 `$done` |
| `RequestCache.CooldownSeconds` | 30 秒 | 连续两次相同请求失败后冷却；401/403/429 立即冷却；最高 120 秒；0 禁用 |
| `RequestCache.Diagnostics` | 关闭 | 每次执行最多输出一条统计汇总 |
| `Region.Fallback` | Auto | country 缺失时的保守判断；可选 Locale、CN、HK、MO、TW |

Loon 使用明确的 String input、Boolean switch、String select。原有参数顺序保持不变，新参数追加在原有 `RequestCache.TTL` 后。最低版本声明为 Loon `3.5.1(983)`；系统版本沿用上游。

## 失败、预算与回退

处理一份响应时，JSON、预警网页、WAQI 鉴权请求及必要的地区网格下载共享协调器。最多 3 个活跃请求、16 个在途或排队请求。每个 Loon 原生请求的 timeout 取 5000 毫秒与剩余预算的较小值；队列拿到执行机会时重新检查预算，少于 250 毫秒时不再发起网络请求。已经发出的请求始终等待原生回调，再结束脚本。这是发起后续请求的应用预算，不是原生取消功能，也不保证宿主在某个精确时间回收所有资源。

每个天气数据项先取得隔离的副本，供应商失败或异常时保留对应的 Apple 原始数据；所有并发数据项均处理完后才完成脚本。整份响应没有有效变化时直接保留原始二进制字节。空气质量的昨日比较失败时保留原有比较值，不丢弃已取得的当前数据。预警详情请求获取失败时透传原请求，不构造空数组成功响应；真实、经过验证的无预警结果仍可正常返回。

如果 Apple 对应数据仍然可用，优先保留；当原始数据也缺失或不可用时，只有另一数据源存在用户明确配置且不同于上游共享默认值的令牌，才尝试一次备用查询。不会在两种来源之间循环重试，不会自动申请密钥或付费权限；备用查询也共享预算与冷却。诊断中另计备用尝试与成功次数。

失败状态只保存请求摘要、计数与时间，独立 Key 为 `WeatherKit.ProviderFailures.v1`，最多 32 条、8192 字符、120 秒窗口。城市、数据源、语言、鉴权信息和路由选择参与请求身份隔离；更换凭据不会沿用旧凭据的冷却。429 的 Retry-After 会参与冷却计算，但最长 120 秒。成功可恢复对应请求。HTTP 错误正文和整体无效结果不进入响应缓存；共享响应的部分子项失败时，可以缓存其正常数据，但每次读取都按当前数据项重新校验，失败子项始终不可用。过期正文不作为兜底。

## 网页预警与缓存淘汰

默认 QWeatherWeb 链路使用同一预算与请求合并。先校验状态、HTML Content-Type、已知页面结构与 UTF-8 正文大小，再提取预警记录；只缓存验证后的结构化记录。页面变化、登录/拦截页面、非 HTML、网络错误均标记不可用。UTF-8 大小计算不依赖 TextEncoder，正文边界仍为 2 MiB；边界检查发生在原生返回正文之后，不是宿主接收时的内存限制。

JSON 及结构化预警仍沿用八条响应、单条 96 Ki UTF-16 字符、总快照 256 Ki 字符等上限。普通 JSON 最多处理 1 Mi 字符，地区网格下载单独最多 2 Mi 字符。缓存遵守上游 no-cache/no-store、max-age/Age 和 Vary:*。有效期不因命中续期；预警在合并和构造详情时再次排除明确过期或时间无效的第三方记录。

缓存条目按哈希后的城市坐标或预警地区标识分组，组内优先保留最近使用的数据，组间轮流分配现有八个槽位。没有扩大宿主缓存容量。Loon 各次执行没有共享 Promise 或持久化事务；同步读、合并后写只能减少覆盖，少量并发覆盖最多导致额外查询。

## 地区识别与诊断

明确的 `country` 请求参数优先。Auto 模式再使用同一坐标此前确认的地区，随后查询离线 Natural Earth 多边形；靠近边界和海岸的点不推断，最后回到语言区域。没有使用覆盖亚洲的大矩形强制判定 CN，也不使用设备或代理出口 IP 推断所查询城市。

地区记录 Key 为 `WeatherKit.RegionHints.v1`，最多 32 条、8192 字符、7 天；记录只含坐标的哈希、地区代码与时间。离线数据为公共领域资料，固定来源、简化精度与边界排除范围见 [provider-regions-source.json](provider-regions-source.json)，可用 `python3 scripts/build-provider-regions.py` 复现。地图仅用于保守的天气数据源路由提示，不作为权威行政边界。对澳门等面积小、边界密集的位置，明确参数、同坐标记录或用户手动选择优先于几何推断。

诊断汇总包含请求数、缓存命中、在途合并、累计网络耗时、执行耗时、失败类型、冷却/预算跳过和数据项回退次数。使用固定的名称与错误分类，不包含 URL、响应正文、令牌或原始坐标；不向外部服务发送统计。汇总开关独立于上游的高级 LogLevel 调试输出。

## 验证边界

构建会运行完整回归，以及实际压缩的请求、响应、自定义标尺三个 bundle 的模拟 Loon 检查。覆盖网页预警、跨次缓存、失败透传、地区识别、原始二进制保留、已有分钟数据短路、配置备用来源补全、HTTP 错误正文隔离与共用接口的子项失败隔离；检查原生回调结束后仅调用一次 `$done`。最终次数和通过结果以 [构建验证记录](loon-build-validation.json) 为准。

模拟环境没有 Node、WebCrypto 或宿主 TextEncoder；提供 URL、URLSearchParams 与 TextDecoder。FlatBuffer 编码使用有界 UTF-8 兼容实现（仅宿主缺少 TextEncoder 时安装），覆盖 Unicode 代理对与孤立代理字符；单次字符串编码最多 2 MiB。设置合并使用独立副本，连续执行不会修改共享默认值或继承前次凭据。

原生规则另外检查实际导入文件中的表达式、正则路由、参数保留与系统 jq 的转换结果；这不是 Loon 原生配置解析器，也不能证明手机已成功导入。处理开销测量使用真实源码和实际 bundle、模拟 HTTP 回调与存储，不对真实天气 API 发出请求。

CI 使用锁定的原始上游 schema `@nsringo/weatherkit@1.1.2` 重新测试与构建。最终发布的来源提交、bundle 验证与 SHA-256 保存在构建来源文件和 `docs/loon-build-validation.json`。桌面模拟、CI 和资源字节校验均不等于真实 iPhone 的天气显示、耗电、延迟或 VPN 连续运行结论。

## 官方文档核对

2026-10-19 核对 [Loon Rewrite](https://nsloon.app/docs/Rewrite/rewrite_v2/)、[Loon Script](https://nsloon.app/docs/Script/script_v2/)、[Script API](https://nsloon.app/docs/Script/script_api/) 与 [插件](https://nsloon.app/docs/Plugin/)。原生 Rewrite 使用官方 `response.json.jq`、`${request.method}`、必选 URL Guard 与 `${scale.1}` 命名捕获；只替换 URL 匹配部分并保留查询后缀。Rewrite 语法要求 3.5.1(978)，本插件最高要求仍为 Script 的 3.5.1(983)。独立入口直接使用 Loon 原生 `$done`，没有依赖跨客户端完成适配。只使用公开的原生 HTTP callback、毫秒 timeout、字符串持久化存储及一次性完成接口。未使用取消请求、定时器竞赛、全局存储清空或其他客户端的私有配置项。
