## 用户可见行为

新增 `WeatherAlerts.Language`，原有 12 项参数的名称、类型和默认值保留，候选合计 13 项。已删除的请求缓存等 9 项附加控制及其行为继续保持删除。

| 设置 | 候选行为 |
| --- | --- |
| `Auto`（默认） | 使用原有请求语言与来源处理；旧配置未保存新字段、字段为空或不支持时也沿用此行为。 |
| `zh-Hans` | 仅向当前选定的预警来源请求其简体中文版本。 |
| `en` | 仅向当前选定的预警来源请求其英文版本。 |

这是来源语言偏好。来源可能继续返回原文或混合语言，候选保留实际文字、签发单位、时间和来源链接，不删除未翻译的正文，也不调用外部翻译服务。Apple 原始天气横幅标题、其他天气产品语言及详情页面自身的标签由各自已有设置决定，不能保证它们与本参数同步。

显式语言模式下，来源没有提供可靠的逐段语言元数据，REST 消息使用 `und`，避免把请求语言冒充正文的已确认语言。Auto 保留旧消息语言行为。实际缓存的 Apple 页面 `processData` 方法离线回放接受该标记并保留全部三段文字，但这项回放不等同于新候选在 Safari 或 Weather App 中通过验收。

## 实现范围与来源依据

- `weatherAlertLanguage.mjs` 只识别明确支持的语言及常用别名；Auto 返回原参数对象，显式偏好只复制并修改预警所需的语言字段。
- `createProviderEnvironment.mjs` 增加按需建立的预警专用来源实例。Auto 复用原实例；显式偏好隔离预警语言，避免改变同时处理的实况、小时、每日、空气质量和分钟降水请求。
- WK2、WK3 及开发版预警入口使用上述实例。详情入口请求对应来源路径，保留已有来源与端点；仅显式偏好覆盖本次预警的 Accept-Language，不修改 User-Agent。
- QWeatherWeb 的中文默认路径和英文 `/en/` 路径分别请求。原有 QWeather API `/weatheralert/v1/current/{latitude}/{longitude}` 与彩云 API 继续使用各自已有语言映射。
- 现有 ProviderTransport 不保存已完成的响应。共享 transport 的中文和英文测试分别产生独立请求；没有增加缓存或在途合并。显式语言详情响应使用 `Cache-Control: no-store`，避免同一 Apple 详情 URL 在偏好改变后继续复用旧实体；Auto 保留 `max-age=0`。
- Loon、Surge、BoxJS 的候选声明和参数传递同步更新。没有新增宿主 API、最低版本、依赖、来源、MITM 域名、并发、重试或请求预算。

2026-11-14 核对：[和风实时预警](https://dev.qweather.com/docs/api/warning/weather-alert/)提供原有端点及 `lang`；[和风预警语言说明](https://dev.qweather.com/en/docs/api/warning/alert-guide/)明确预警覆盖可能小于通用语言列表，返回语言可能不同于请求语言或包含多种语言。[彩云预警文档](https://docs.caiyunapp.com/weather-api/v2/v2.6/5-alert.html)列出来源语言参数，并将预警说明列为来源原文；文档存在语言参数不等于每条预警都有译文。原生参数使用既有 string select 和脚本参数对象，遵循 [Loon 插件官方文档](https://nsloon.app/docs/Plugin/)。
