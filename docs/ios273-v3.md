# iOS 27.3 Beta 的 WeatherKit v3 兼容

2026-11-04，用户授权在 iPhone 镜像和 Loon 请求记录中排查“天气能显示、插件功能不生效”。实际请求已转为 `/api/v3/weather/`，原响应为 `application/vnd.apple.flatbuffer;messageType=WK3.Weather`。旧插件只处理 v2；WK3 的字段和枚举布局也有变化，不能将路径简单扩展后交给 WK2 解码器。上游同日的 [issue #106](https://github.com/NSRingo/WeatherKit/issues/106) 有相同症状，排查时尚无修复。

## 处理方式

Loon 原生 Rewrite 只为 HTTPS `weatherkit.apple.com/api/v3/weather/` 的 GET 请求设置 `Accept: application/json`。Apple 在同一次请求中返回自己的 JSON 表示；没有重发请求、转换服务或额外的 Request JavaScript。v3 用文本 Response Script，原有 v2 仍用二进制 Script。

JSON 路径复用已有数据源、缓存、地区判定、失败回退和网络预算。按 WK3 实际字段类型把天气状态和降水类型转换为数组，把供应商的单点降水量和降雪量转换为 expected/minimum/maximum 相等的统计对象，坐标元数据写成数值。Apple 已有的区间、未替换预报行和其他产品保留。供应商结果中的非有限数值不写成 JSON null。

没有改动时直接返回原正文及头部；改动后保留其他头部，移除失效的长度和缓存验证标记，设置 `Cache-Control: no-store`。未知格式、非 200、无有效产品、超限和供应商失败均保留 Apple 数据。Apple 若不接受 JSON 协商，WK3 二进制原样放行，不会误送入 WK2。

## 开销边界

新增原生请求头规则没有后台任务、轮询或额外网络往返。继续使用既有缓存、3 个原生请求槽和总预算。JSON 输入与输出最多 1,048,576 个 UTF-16 码元、4 MiB UTF-8；每产品累计数组元素最多 8192，深度最多 64，遍历节点最多 100000。只对有机会处理的产品遍历；空气质量因已有算法会修改对象而复制，其他产品沿用按需合并。

这些是脚本工作边界，无法限制 Loon 已接收正文的原生缓冲。JSON 表示可能比二进制更大；本次修复没有测得 iPhone 内存或耗电下降，不将协议兼容称为省电比例。

## 官方文档核对

2026-11-04 核对 [Rewrite](https://nsloon.app/docs/Rewrite/rewrite_v2/)、[Script](https://nsloon.app/docs/Script/script_v2/)、[Script API](https://nsloon.app/docs/Script/script_api/) 与[插件](https://nsloon.app/docs/Plugin/)。请求头修改使用官方 `request.header.set`；保留原有受支持的 Loon Script 语法和全部参数，v2/v3 URL Guard 互斥，v3 读取文本正文。最低版本保持 3.5.1(983)，所有原生异步 HTTP 回调结束后单次 `$done`，没有引入取消请求或未公开配置字段。

## 验证边界

- 本地 234 项回归通过，覆盖 v3 类型、空气质量重算、部分预报替换、未知字段、失败保留原文及处理上限。
- 授权取得的 Apple v3 JSON 仅在本地忽略目录做离线回放：空气质量可修改，其他产品语义保持一致，供应商网络使用失败桩。原始响应、授权头和精确位置不进入 Git 或发布资产。
- 临时手机传输探针：用户刷新后天气正常；Loon 实际返回 200、application/json 和 gzip。此时仅证明协议协商与天气读取，尚不能代表正式数据替换、活跃预警和所有地区已实机通过。
- 正式构建、发布校验及正式插件的设备结果记录在发布提交的构建验证记录中。


## 正式版本的手机结果

2026-11-04，在 Loon 3.5.4(1015) 的 Tunnel 中看到 iOS 天气请求命中 `api.v3.weather.json.response`，运行文件固定为 cache-v8，状态 Completed。单次记录耗时 273 ms，统计为 4 次供应商请求、0 次请求失败、1 次合并、1 次持久缓存命中。原网络响应带 gzip、Content-Length 为 34992，修改后长度为 320842；脚本日志另报告接收正文总量 313555（Loon 统计口径，不据此认定原 Apple 正文的解压长度）。Loon 分别展示原/修改后响应，修改后为 200/application/json、Cache-Control: no-store。天气页面实况、小时及每日预报能够显示。这证明本轮已执行实际改写，不是只命中路径。

已有 EAQI 算法会对标准未定义的 CO 输出警告和 category -1 日志，该次脚本仍完成。这里没有据此宣称空气质量卡片的所有字段、活跃预警、每个地区都已逐项实机验收。单次运行时长及客户端内存计数也不构成设备峰值、耗电改善或长期 VPN 稳定性证明。

手机订阅已从临时传输探针恢复为 main/Loon/script/WeatherKit.lpx，重新加载的构建日期与正式 v8 相符，临时统计开关为关闭。main、固定 cache-v8 和 Release 的八个文件分别通过公开字节核对。手机抓包原始授权文本已删除，本地临时接收服务已停止。
