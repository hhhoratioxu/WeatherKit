# iOS 27.3 Beta 的 WeatherKit v3 兼容

2026-11-04，用户授权在 iPhone 镜像和 Loon 请求记录中排查“天气能显示、插件功能不生效”。实际请求已转为 `/api/v3/weather/`，原响应为 `application/vnd.apple.flatbuffer;messageType=WK3.Weather`。旧插件只处理 v2；WK3 的字段和枚举布局也有变化，不能将路径简单扩展后交给 WK2 解码器。上游同日的 [issue #106](https://github.com/NSRingo/WeatherKit/issues/106) 有相同症状，排查时尚无修复。

## 处理方式

Loon 原生 Rewrite 只为主天气 App 的 HTTPS `weatherkit.apple.com/api/v3/weather/` GET 请求设置 `Accept: application/json`。Apple 在同一次请求中返回自己的 JSON 表示；没有重发请求、转换服务或额外的 Request JavaScript。v3 用文本 Response Script，原有 v2 仍用二进制 Script。

JSON 路径复用已有数据源、缓存、地区判定、失败回退和网络预算。按 WK3 实际字段类型把天气状态和降水类型转换为数组，把供应商的单点降水量和降雪量转换为 expected/minimum/maximum 相等的统计对象，坐标元数据写成数值。Apple 已有的区间、未替换预报行和其他产品保留。供应商结果中的非有限数值不写成 JSON null。

没有改动时直接返回原正文及头部；改动后保留其他头部，移除失效的长度和缓存验证标记，设置 `Cache-Control: no-store`。未知格式、非 200、无有效产品、超限和供应商失败均保留 Apple 数据。Apple 若不接受 JSON 协商，WK3 二进制原样放行，不会误送入 WK2。

## 开销边界

新增原生请求头规则没有后台任务、轮询或额外网络往返。继续使用既有缓存、3 个原生请求槽和总预算。JSON 输入与输出最多 1,048,576 个 UTF-16 码元、4 MiB UTF-8；每产品累计数组元素最多 8192，深度最多 64，遍历节点最多 100000。只对有机会处理的产品遍历；空气质量因已有算法会修改对象而复制，其他产品沿用按需合并。

这些是脚本工作边界，无法限制 Loon 已接收正文的原生缓冲。JSON 表示可能比二进制更大；本次修复没有测得 iPhone 内存或耗电下降，不将协议兼容称为省电比例。

## 早期本地稳定性修复（历史阶段）

2026-11-04，用户反馈正式 v8 仍偶尔无法显示天气；手机桌面组件也实际出现 Weather Unavailable。上面的单次成功记录不代表持续稳定性通过。用户要求先停止上传，修复并验证后再发布；本节改动只在本地分支，未更新订阅、发布资产或向上游提交 PR。

彩云小时及每日分段云量为 0–1 比例，旧转换可将 0.38 直接写入 WK3 JSON。通过本机 macOS 27.3 的 WeatherData 框架导出符号核对，WK3 的云量、湿度、降水概率为 Int8，紫外线指数为 UInt8，风向为 UInt16，时间为 UInt32，温度、气压及风速为 Float。这里是原生字段类型证据，并非完整 iOS 解码器验收。小时及每日云量现转换为整数百分比；原本已是百分比的降水概率不重复乘 100。

JSON 适配同时规范已知整数范围、移除 WK2 中代表“无结束时间”的可选时间零值，并在写回前按产品校验。缺失值不覆盖 Apple 已有字段；无效数组、数值、枚举、统计区间或 Unicode 只使该产品回退，其他健康产品继续处理。改写文本时移除旧 bodyBytes，避免正文存在两个不一致的表示。没有任何改动时仍保留完整原文与缓存验证头。

v3 请求头协商和响应脚本限定到 User-Agent 前缀 WeatherKit_Weather_iOS_。规则排除此前观察到的 destinationd、watchOS 及未知后台客户端的 User-Agent，使这些客户端保留 Apple 原有传输格式，不启动 v3 正文脚本；该排除已通过规则夹具检查，尚未全面取得候选启用后的实际后台记录。响应规则还要求 GET、200 和 application/json，减少无用 JavaScript 初始化。自定义数据替换因此暂限主天气 App；本轮没有实现组件或手表的 WK3 二进制替换，也不能假设所有组件均使用不同的 User-Agent。

## Mac 实测对 JSON 结构结论的修正

2026-11-05，按用户要求改用 Mac 原生验证。系统日志表明，WeatherData 的 WK3 FlatBuffer 类型不能直接作为天气主应用 JSON 读取器的契约：后者要求字符串状态和标量降水；原始 v3 JSON 的状态数组、统计对象及缺失的每日降水总量会造成解码失败并回退到 CloudKit。故本文早期的“数组和统计对象”适配只对应 WK3 的 FlatBuffer 表示，不是已通过的主应用 JSON 输出格式。

第二版候选修正该协议桥接，并转换已知的未替换分时产品。旧手机候选的页面显示和 Loon Completed 记录不作为全部修改被系统采用的证明；Mac 的新发现与待完成的第二版原生验收详见 [v9 记录](air-quality-v9.md)。
