# WK3 失败回退的临时分配优化与量测

日期：2026-11-16，Asia/Shanghai。基准为已发布 v3.3.7 的 `5d42a422a46787bfd6b23eb291c3cfbeee9f17fc`，本地及远端 main 在开始时一致、工作区干净。下文保留本地量测阶段的证据。用户随后授权将同一优化交付为 v3.3.8，并同步 PR #107；没有更新客户端或使用 Mac UI。

## 已确认的重复工作

WK3 JSON 先将 Apple 的状态数组、降水统计和 periodic 字段适配为原生读取器格式。当存在供应商替换目标时，原实现先生成一份有界、已适配的 Apple 回退回应，保护后续输出超限／无法序列化时的失败降级。供应商全部失败或返回相同数据时，结束阶段仍再次序列化同一份 Apple 数据。

本地实际发布脚本回放确认了这条路径：273 小时和 periodic 数据、约 552 KiB 输入的大样本中，回应正文序列化两次，累计 1,141,624 字符；两次都生成相同内容。这是已确认的重复分配，不把原版可正常显示天气描述为功能失效。

`src/process/ResponseJSONV3.mjs` 现在独立记录供应商是否真正安装了不同的有效产品。所有替换都失败或无变化时，等待所有回调后返回已经生成的 Apple 回退；有有效替换时仍重新编码最终结果，并保留原有输出超限的安全回退。原始正文已经兼容且没有变化时，继续返回原回应及其验证头。

该复用只在一次执行内使用既有回应对象；没有增加跨请求缓存、在途合并、重试、后台工作、持久存储或用户参数。来源、端点、原 13 项设置、Loon／Surge 原生 API、超时单位、最低版本和版本号均未改变。

## 实际量测

通过 `scripts/measure-json-memory.mjs` 执行旧版与候选的实际 Loon 压缩脚本。输入是程序生成的公开协议夹具，包含 273 小时、periodic 和需要保留的未知字段；所有 HTTP 回调使用本地模拟，不发真实网络请求。CPU 模式没有分配采样或运行中 GC；内存模式以 4096 字节间隔采样，包括已回收对象与框架开销，并在回调等待和完成后完整 GC。输入和 VM 编译在初始 GC 前完成。

macOS arm64、Node v22.23.5/V8；四种场景、两版、CPU／内存两种模式，每组七个独立子进程并交替执行，共 112 个主测样本。表中为中位数；采样分配为 KiB，CPU 为毫秒。

| 场景 | 正文序列化次数 旧 → 新 | 采样分配 旧 → 新 | 首轮 CPU 旧 → 新 |
| --- | ---: | ---: | ---: |
| 普通大小、需要适配、来源失败 | 2 → 1 | 1502.1 → 1548.5 | 11.171 → 10.696 |
| 大回应、需要适配、来源失败 | 2 → 1 | 3094.0 → 2523.0 | 17.879 → 15.005 |
| 来源成功 | 2 → 2 | 1650.2 → 1679.4 | 13.291 → 13.524 |
| 已兼容的 Apple 回应、来源失败 | 0 → 0 | 1220.4 → 1251.9 | 7.500 → 7.873 |

大回应失败场景少序列化 570,812 字符，采样分配下降约 **18.5%**。普通大小场景和对照场景没有观察到同等分配收益；采样波动与框架开销不能当成精确累计分配。等待回调时及完成后保留堆的中位数变化均不足 0.1%，因此本轮没有常驻／保留堆下降的结论，也没有测量实际客户端峰值。

首轮对照路径 CPU 有小幅变化，随后仅对 CPU 做针对性复核：三种场景每版 21 个独立子进程、交替顺序，共 126 个额外样本。没有同时进行构建或测试。

| CPU 复核场景 | 旧中位数（四分位区间）ms | 新中位数（四分位区间）ms |
| --- | ---: | ---: |
| 大回应、来源失败 | 17.774（17.575–18.443） | 14.841（14.694–15.171） |
| 来源成功 | 13.452（13.121–13.730） | 13.775（13.256–13.945） |
| 已兼容回应、来源失败 | 8.231（7.919–8.524） | 8.081（7.713–8.327） |

大回应失败 CPU 中位数减少约 16.5%；成功路径中位数增加约 2.4%，已兼容失败路径减少约 1.8%，两个对照的四分位区间均重叠，不宣称全路径 CPU 或实际代理延迟改善。所有 238 个正式样本中，两版在相同场景的完整输出 SHA-256 相同，来源调用和完成次数都为一次，已完成回调后没有待处理请求。

## 回归与边界

- 当前候选完整本地测试 **436/436**，失败 0、跳过 0；实际生成的 Loon 脚本 **52/52**、规则／jq **15/15**，Surge 脚本 **41/41** 通过。
- 新增两条不同回调顺序的保护用例：一个产品返回空结果、另一个抛错时，等待全部完成，保留已适配的 current／hourly／periodic 及未知产品；移除旧验证头和 bodyBytes，保留其他头及原始输入。旧版与候选都通过这两条保护测试，确认原有回退语义保持。
- 成功替换、无变化、格式异常、超限回退、预警、AQ、降水、304／ETag、超时和一次完成继续由完整及实际编译回归覆盖。本轮没有进行真实天气请求、网络切换或客户端故障注入。
- Node/V8 采样分配不是 Loon／Surge／JavaScriptCore 的原生内存或峰值，也不是 iPhone、Apple Watch、VPN 稳定性或耗电测量。本轮只确认这条失败回退路径少了一次临时字符串生成。

完整原始样本、复核与校验结果见 [量测 JSON](json-fallback-memory-2026-11-16.json)。复现方式：在相同工具链构建基准和候选后运行 `node --expose-gc scripts/measure-json-memory.mjs BASELINE_BUNDLE CANDIDATE_BUNDLE OUTPUT_JSON`。所有输入均为自写夹具，不包含真实凭据或设备抓包。
