## 删除的 9 项参数及用途

| 原参数 | 用途 | 删除后的行为 |
| --- | --- | --- |
| 实况与空气质量缓存，60 秒 | 短时间内复用成功响应，减少重复查询 | 每次需要第三方数据时独立请求 |
| 小时与每日预报缓存，180 秒 | 复用变化较慢的预报 | 不再复用这层短时缓存 |
| 分钟降雨缓存，15 秒 | 减少频繁刷新带来的重复降水查询 | 按本次请求取得降水数据 |
| 天气预警缓存，15 秒 | 复用验证过的 JSON/网页预警 | 重新查询；失效时保留 Apple 数据 |
| 网络发起预算，8000 毫秒 | 队列和后续查询共享发起预算 | 删除预算与队列；保留每次请求的正常超时 |
| 失败冷却，30 秒 | 失败或限流后临时跳过同一接口 | 后续请求可立即再次尝试所选来源 |
| 输出运行统计 | 汇总缓存、请求数、耗时、回退原因 | 不再生成这份额外统计，原 LogLevel 保留 |
| 缺少 country 时，Auto | 根据坐标、边界及存储记录额外推断地区 | 只用请求 country 或语言地区；原预警详情默认规则保留 |
| 允许备用查询 | 所选来源失败时尝试已配置凭据的另一个来源 | 不切换来源，失败时保留 Apple 数据 |

删除范围包括参数、类型、默认设置、模板、运行时逻辑及专用测试/量测工具。短时响应缓存连同在途合并、持久响应快照、失败状态、诊断计数、地理边界表和备用查询模块一起移除。旧参数即使仍在用户持久存储或参数字符串里，也没有运行时代码读取它们；没有主动改写或清空用户存储。

## 保留的行为

原有 12 项插件参数及默认值、数据源和 endpoint、空气质量算法、污染物浓度、WK3 JSON 适配、降水、预警和详情、periodic 兼容处理继续保留。此次没有把所有天气增强回退到上游，也没有删除原有功能。

供应商请求改用无状态 `ProviderTransport`，只检查 HTTP 状态、正文类型/大小和各产品格式，不保存响应、不合并请求、不重试、不创建冷却状态。正常的单请求超时仍在客户端原生边界处理：Loon 毫秒、Surge 秒；现有默认 5 秒。所有已发请求等待原生回调后才完成脚本。失败路径保留 Apple 的数据与相应 HTTP 校验标头；正文发生变化时清除旧实体标头。

原有 QWeather 城市位置网格的 30 天缓存及 ETag/304 流程继续保留，它不是截图的天气响应短时缓存。保留合法缓存实体检查、大小写不敏感的 ETag 读取、304 空正文处理和损坏缓存拒绝测试。原有昨日空气质量对比数据、macOS 请求阶段补齐 country 的兼容路径及宿主 HTTP 缓存行为不在此次删除范围。

删除缓存、合并和冷却之后，重复刷新或多个产品共用一个接口时可能增加请求数，网络错误时也可能更频繁访问所选来源。删除本身不证明设备更快、更省电或更稳定；没有宣称这类改善。没有有效凭据的地区、来源或设备功能不作实机验证承诺。
