# WeatherKit v5 内存分配优化

2026-10-19。基线为上一版 `cache-v4` 主分支提交 `24be1f0f03a0cf6a97cead4572873c9bcec166dc`。这一轮减少重复数据图和短命对象，不缩减预报内容、不延长缓存时间、不改变网络预算或并发数。

## 改动

- 小时／每日预报不再提前深复制完整 Apple 数据。时间匹配时只创建将被替换的行和必要的日间／夜间子对象，未修改行和字段只读复用；两种来源都不被修改。供应商失败时继续保留 Apple 原始数据。实况使用既有合并新对象的路径；会修改原对象的 AQI 和预警仍保留隔离副本。
- 供应商校验解析出的 JSON 直接交给该消费者的转换代码，不再在保存缓存和转换时重复解析。每个消费者仍有独立的解析对象，格式、长度、状态、有效期与产品结构都独立检查；对象不会保存在缓存条目或跨消费者共享。持久化格式仍为既有原始 JSON 字符串，令牌响应仍不缓存。
- 小时／每日预报解码对同一行复用 schema 视图，避免每读一个字段就创建一个包装对象。每个产品累计解码的向量项上限为 8192；数量不合法或超预算时停止该产品的解码，未取得有效替换时保留原始根表，其他正常产品继续处理。此数量界限也不是宿主内存保证。
- 关闭高级调试时，跳过数据对象的 JSON 调试字符串构造，而不只是跳过日志输出。
- 二进制天气正文超过 4 MiB 时保留原始响应，在设置加载、解码和替换之前退出。4 MiB 是脚本自定的处理边界，不是 Loon 或其他客户端的内存上限。宿主可能已经持有完整正文，无法据此保证宿主峰值。

## 测量方法

[memory-work-measurements.json](memory-work-measurements.json) 保存每个子进程样本、两版中位数、源码及编译产物 SHA-256。在 `cache-v5` 固定版本工作目录运行 `node scripts/measure-memory-work.mjs`，脚本在独立子进程中加载实际压缩的响应 bundle，或由真实供应商源码生成的浏览器 bundle；HTTP 和同步存储由模拟 Loon 环境提供，不访问真实供应商。

每个场景、每个版本分别启动五个新 Node 进程。样本和 VM 在测量前准备好；完整 GC 后记录基线，在唯一原生回调尚未返回、以及脚本完成后再次完整 GC，分别记录仍保留的 V8 堆增量。使用 V8 Inspector 按 4096 字节采样处理过程的分配，包含已经被回收的对象和测量框架开销，是统计估算，不能当作精确分配字节或峰值内存。

真实响应场景含 273 小时、85 分钟的 FlatBuffer。分别重放供应商失败和只替换前 24 小时的成功响应，检查一次 HTTP 请求、一次完成、正确的替换值，以及未替换值和失败原字节。另有六个并发实况消费者共用一次请求的场景，统计特定响应正文的实际解析次数和总解析字符数。

## 结果范围

待网络回调时保留的堆、总分配采样和完成后保留的堆是不同指标。消除临时副本可以显著减少等待期间的存活对象和处理分配，但完成后仍需保留代码、结果和有效缓存，不会下降到零。六消费者场景中，解析次数从 13 次降为 6 次；单个小时预报成功场景从 3 次降为 1 次。每个消费者独立校验，因此不将六次降为共享一次。

原始记录同时保留改善和小幅回退，不只挑选最佳样本。V8 与 iPhone 的 JavaScriptCore 实现不同；这些数据不能换算成 Loon 进程内存、手机内存下降比例或 VPN 稳定性结论。宿主的 HTTP、解压和原始正文缓冲不在本次 V8 堆测量范围内。
